# Vacancy Bot

Личный Telegram-бот, который читает публичные каналы с вакансиями, отбирает новые публикации по **вашим ролям и ключевым словам** и присылает короткие карточки со ссылками. При желании прикладывает один TXT с черновиком сопроводительного письма на русском или английском.

Профессия не зашита в код: можно настроить QA, дизайн, разработку, маркетинг, бухгалтерию или другое направление. Принадлежность профессии к примерам не означает, что бот умеет безошибочно понимать любые объявления: нужно подобрать названия ролей, их варианты и проверить результат на своих источниках.

В репозитории нет действующего токена, получателя, личного резюме, истории вакансий, базы, конфигурации сервера или чужого карьерного профиля. Примеры вымышленные. После клонирования бот **не начнёт рассылку**: каналы и роли пусты, доставка и модель выключены.

**Для агента:** начните с [AGENTS.md](AGENTS.md) и [docs/AGENT_CONTEXT.md](docs/AGENT_CONTEXT.md). Для внутреннего устройства и обслуживания: [архитектура](docs/ARCHITECTURE.md), [эксплуатация](docs/OPERATIONS.md).

## Что получает пользователь

```text
💼 Product Designer at Example Studio
🌍 Location: Remote
💰 Salary: EUR 3000

🎯 Роль: Product Designer · Figma · UX research

🔗 https://t.me/demo/2
```

Это вымышленный пример оформления. Неизвестная зарплата или локация не заполняются догадками. Если включены письма, отдельным ответом на карточку приходит `Cover_Letter_..._RU.txt` или `..._EN.txt`. Текст письма в чат не дублируется, CV/PDF не отправляется. Отклики работодателю бот не делает.

## Как это работает

1. Программа получает публичную HTML-страницу `https://t.me/s/<channel>`. Вход в пользовательский Telegram-аккаунт не нужен; бот не добавляется администратором каналов.
2. Первый успешный просмотр каждого нового канала сохраняется как исходный снимок **без отправки старых постов**. Неудачная загрузка не считается первым снимком.
3. При следующих проверках новые посты и правки сравниваются с SQLite. Правила ищут основную должность в начале объявления, затем проверяют обязательные и исключающие фразы.
4. Опциональная локальная модель уточняет соответствие вашему профилю и выбирает короткие дословные выдержки обязанностей. Её запрос не содержит списка «правильных профессий» от автора.
5. Если включены письма, фоновый поток подготавливает TXT. После его готовности бот отправляет карточку, сохраняет её ID и загружает файл ответом на неё.
6. Результаты подготовки, очереди и отправки сохраняются. Перезапуск не означает повтор всей истории.

Проверка одного канала — не чаще раза в 60 секунд; запросы к разным каналам разнесены. Во время работы модели чтение источников продолжается. Задержка уведомления зависит от интервала, очереди, доступности Telegram и скорости модели. Это опрос, а не мгновенная подписка на события.

## Требования

- Python **3.11+**. В рабочем коде только стандартная библиотека; обязательных Python-пакетов нет.
- Linux для постоянной службы: блокировка процесса использует `fcntl`. Офлайн-пример, парсер и тесты работают также на Windows.
- Исходящий HTTPS к `t.me` и `api.telegram.org`. Открывать входящие порты не требуется.
- Свой бот, созданный через **@BotFather**, и свой личный Telegram-чат.
- Опционально — Ollama на этом же компьютере с заранее установленной моделью, поддерживающей используемый JSON-режим. Сервис сам модели не скачивает.

Docker, Kubernetes, Grafana, внешний SQL-сервер и платный API для базовой работы не нужны. Их установка в этот репозиторий не входит.

## 1. Получить код и проверить без Telegram

Linux:

```bash
mkdir -p "$HOME/apps"
git clone https://github.com/kurkiniliya-arch/vacancy-bot.git "$HOME/apps/vacancy-bot"
cd "$HOME/apps/vacancy-bot"
python3 --version
python3 -m unittest discover -s tests -v
mkdir -p .local
python3 -m jobbot --config examples/demo.toml --snapshot examples/baseline.json --database .local/demo.sqlite
python3 -m jobbot --config examples/demo.toml --snapshot examples/new.json --database .local/demo.sqlite
```

Первая команда с `--snapshot` создаст исходный снимок без карточки. Вторая покажет одну подходящую вымышленную вакансию в терминале с отметкой `НЕ ОТПРАВЛЕНО`; вакансия менеджера продаж не пройдёт. Повтор второй команды не создаёт ещё одну запись очереди, хотя уже имеющаяся запись снова отображается в просмотре.

На Windows используйте `python` вместо `python3`, а каталог создайте командой `New-Item -ItemType Directory -Force .local`. Саму постоянную службу запускайте на Linux. Команды выполняются из корня клонированного репозитория. Установка через `pip` для запуска из этой папки не требуется.

## 2. Задать свои каналы и профессию

```bash
cp config.example.toml config.local.toml
```

Отредактируйте `config.local.toml`. Каналы указываются **без `@` и без `https://t.me/`**. Используйте реальные имена выбранных вами источников, а не демонстрационный `demo`.

Пример блока для дизайнера:

```toml
[matching]
target_roles = ["Product Designer", "UX Designer", "Продуктовый дизайнер"]
excluded_roles = ["Sales Manager"]
keywords = ["Figma", "UX research", "design system"]
required_keywords = []
excluded_keywords = []
allow_keyword_only = false
```

Для другой профессии замените этот блок. Например, тестировщик может выбрать `target_roles = ["QA Engineer", "AQA Engineer", "Тестировщик"]`, а разработчик — `target_roles = ["Python Developer", "Python разработчик"]`. QA не исключается автоматически.

| Параметр | Поведение |
|---|---|
| `sources` | Список публичных каналов. Пустой список запрещает запуск. |
| `poll_seconds` | Интервал, целое число от 60. |
| `target_roles` | Варианты нужной должности; хотя бы один обязателен. |
| `excluded_roles` | Исключения по должности в начале объявления. Имеют приоритет при конфликте. |
| `keywords` | Совпадения для объяснения отбора; сами по себе не заменяют роль по умолчанию. |
| `required_keywords` | Все перечисленные фразы должны присутствовать где-то в тексте. |
| `excluded_keywords` | Любая фраза в любом месте текста исключает пост. Используйте осторожно. |
| `allow_keyword_only` | Если `true`, совпадение по `keywords` может пройти без явного нужного заголовка. |
| `delivery.enabled` | Разрешение отправки; дополнительно нужен аргумент запуска `--send`. |

Фразы сопоставляются буквально, без учёта регистра, с нормализацией пробелов и знаков препинания. Это не регулярные выражения и не морфологический поиск: добавляйте распространённые переводы и варианты названия. Например, «продуктовый дизайнер» и «дизайнер продукта» — разные фразы.

Пустые `required_keywords` и `excluded_keywords` не накладывают ограничений. Автоматического минимального порога зарплаты, проверки визы, оценки уровня языка или валютной конвертации нет. Отсутствие зарплаты не повод отбрасывать вакансию. Упоминание «работать с дизайнером» не должно превращать другую должность в дизайнерскую, но эвристика заголовка не гарантирует отсутствие ошибок.

При `allow_keyword_only=true` без модели неоднозначная карточка может быть отправлена по правилам. С моделью такие кандидаты проверяются дополнительно; при недоступности модели или ответе `unclear` остаются на повторную проверку. Для осторожного старта оставьте `false`.

## 3. Проверить выбранные публичные источники

Пока `delivery.enabled=false`:

```bash
python3 -m jobbot.scan --config config.local.toml --database .local/preview.sqlite
```

Это один проход с настоящими HTTP-запросами, но **без Telegram-отправки и без модели**. При первом проходе отсутствие карточек нормально: сохраняется исходный снимок. Позже повторите команду, чтобы увидеть новые публикации. Публичный канал должен открываться в браузере по адресу `https://t.me/s/ИМЯ_КАНАЛА`.

`preview.sqlite`, `demo.sqlite` и будущая `live.sqlite` — разные базы. Нельзя подставить пробную базу в боевой запуск: режим записывается в БД и проверяется.

## 4. Привязать своего бота к своему чату

Создайте отдельного бота в @BotFather. Затем в **своём интерактивном терминале**:

```bash
install -d -m 700 "$HOME/.local/state/vacancy-bot"
python3 -m jobbot.setup --username YOUR_BOT_USERNAME --credentials "$HOME/.local/state/vacancy-bot/credentials.json"
```

Замените `YOUR_BOT_USERNAME` на имя своего бота. Это публичное имя, не токен.

Настройщик проверит отсутствие webhook и спросит, не использует ли этот бот другой процесс. Затем скрыто запросит токен, получит имя бота через `getMe` и покажет одноразовую команду `/start <код>`. Отправьте её именно этому боту и подтвердите, что найденный личный чат — ваш. Если подтверждение не поступит за 5 минут, секретный файл не создастся.

`getUpdates` используется только при привязке. Не запускайте настройщик для уже работающего чужого бота: это может затронуть его очередь входящих обновлений. Пустой webhook не доказывает отсутствие другого потребителя `getUpdates`; поэтому здесь есть отдельное подтверждение владельца. Готовый `credentials.json` не перезаписывается автоматически. На Linux ему нужны права `0600`.

Токен нельзя вставлять в чат с агентом, в командную строку, README, TOML или Git. Он хранится только в отдельном файле. Публикации из каналов не управляют адресатом: отправка разрешена только в подтверждённый личный чат.

Однократная проверка связи, пока служба ещё остановлена:

```bash
python3 -m jobbot.check --credentials "$HOME/.local/state/vacancy-bot/credentials.json" --send-test
```

Эта команда действительно отправляет одно тестовое сообщение. Результат хранится отдельно в `setup-check.sqlite`; повторный успешный запуск не шлёт второе. После неопределённого результата сначала проверьте чат, не удаляйте базу проверки ради автоматического повтора.

## 5. Запустить в терминале

В своём TOML поменяйте только `[delivery] enabled = true`. Затем:

```bash
python3 -m jobbot.runtime --config config.local.toml --database "$HOME/.local/state/vacancy-bot/live.sqlite" --credentials "$HOME/.local/state/vacancy-bot/credentials.json" --send
```

Программа проверит бота и получателя, возьмёт блокировку базы и начнёт читать каналы. Первый боевой проход опять сохраняет исходный снимок без истории, независимо от пробного просмотра. Для остановки в терминале используйте `Ctrl+C`. Для постоянной работы настройте службу ниже; не держите второй экземпляр параллельно на другой базе с тем же ботом.

## 6. Необязательные сопроводительные письма

Скопируйте **вымышленную структуру**, затем полностью замените её своими фактами:

```bash
install -d -m 700 "$HOME/.local/state/vacancy-bot/profile"
install -m 600 examples/profile.example.json "$HOME/.local/state/vacancy-bot/profile/profile.json"
```

Откройте новый `profile.json` локально. После замены всех примеров удалите `example_only` или установите `false`: пока там `true`, программа откажется использовать демонстрационные достижения.

Укажите имя для подписи, ограничения в `constraints` и хотя бы два факта в `facts`. У каждого факта нужны уникальный `id`, список `keywords`, готовые правдивые абзацы `ru`/`en` (до 1200 символов каждый) и краткая тема `topic.ru`/`topic.en`. Идентификаторы произвольные: `sales`, `pastry`, `research`, `support` и т. п.; код не требует конкретных навыков. Короткие латинские ключевые слова ищутся по границам слова, остальные — как подстроки. Факты с совпадениями получают больший вес.

```toml
[applications]
enabled = true
profile_dir = "~/.local/state/vacancy-bot/profile"
use_model = false
research = false
```

С `use_model=false` письмо собирается из должности, известной компании и двух наиболее релевантных фактов профиля. Это простой адресный шаблон, а не глубокое исследование работодателя. Если совпадений нет, используются первые факты профиля — поэтому их порядок тоже имеет значение.

С `use_model=true` модель выбирает два примера и пишет вступление/завершение. **Абзацы о вашем опыте вставляются из профиля без переписывания моделью.** Второй запрос проверяет письмо по фактам и источникам. Если генерация, структура или проверка не удались, используется простой вариант. Проверки уменьшают риск, но не гарантируют отсутствие выдумок во вступлении или неверной интерпретации требований. Прочитайте письмо перед отправкой работодателю.

Поддерживаются RU/EN: язык определяется по основному тексту, а не по одному английскому названию профессии. Для очень короткого анонса может учитываться доступная полная страница вакансии. Другие языки сейчас отдельной настройки не имеют и могут быть ошибочно определены как английский.

Резюме автоматически не разбирается: подтверждённые факты в профиль вносите сами или с агентом после проверки. Ни PDF, ни CV-файл бот не прикладывает.

## 7. Необязательная локальная модель и страницы компаний

Классификатор и автор писем включаются независимо:

```toml
[local_model]
enabled = true
model = "qwen3:4b"

[applications]
enabled = true
profile_dir = "~/.local/state/vacancy-bot/profile"
use_model = true
research = true
```

Нужна уже работающая Ollama на `http://127.0.0.1:11434` с моделью из `model`. Название в примере — исходный проверявшийся вариант, а не обещание качества и не автоматическая установка. Для другой модели проверьте JSON-ответы, поддержку параметров, память и задержки на своих примерах. Сервис обращается к локальному `/api/chat`; внешняя LLM и ключ API не используются. См. [Ollama API](https://docs.ollama.com/api/chat).

`local_model.enabled` управляет только уточнением отбора. `applications.use_model` отдельно разрешает генерацию писем. Явная нужная роль, прошедшая жёсткие правила, сохраняется даже при несогласии модели; неоднозначный кандидат может быть отклонён или отложен. Модель не рассматривает публикации, полностью отсеянные первичными правилами.

Один фоновый поток обслуживает модель и подготовку писем. На CPU это может занимать минуты, а очередь увеличивает задержку. Маленькая модель бывает недостаточно надёжной для свободного написания всего письма — поэтому биография в нём не генерируется заново.

`research=true` разрешает прочитать до трёх публичных HTML/text-страниц по ссылкам объявления с ограничением размера и времени. Это **не общий поиск в интернете** и не браузер с JavaScript. При недоступности страницы письмо строится по самому объявлению. Не выполняются вход, отправка форм или загрузка вложений. Частные IP, localhost, секретные параметры ссылок и перенаправления в частную сеть блокируются; соединение фиксируется на проверенном адресе. Извлечённый текст страницы всё равно остаётся недоверенным источником, а не подтверждением личности работодателя.

## 8. Автозапуск на Linux через systemd пользователя

Шаблон рассчитан на код в `$HOME/apps/vacancy-bot`, Python в `/usr/bin/python3` и текущего обычного пользователя. Если пути другие, сначала измените `WorkingDirectory`/`ExecStart` в копии unit-файла. Не используйте этот шаблон одновременно с уже настроенной системной службой того же бота.

Остановите запуск в терминале. Базу и credentials оставьте на месте — служба использует те же пути:

```bash
install -d -m 700 "$HOME/.config/vacancy-bot"
install -d -m 700 "$HOME/.config/systemd/user"
install -m 600 config.local.toml "$HOME/.config/vacancy-bot/config.toml"
install -m 644 deploy/vacancy-bot.service "$HOME/.config/systemd/user/vacancy-bot.service"
systemctl --user daemon-reload
systemctl --user enable --now vacancy-bot.service
sudo loginctl enable-linger "$USER"
systemctl --user status vacancy-bot.service --no-pager
```

Относительный `profile_dir` разрешается относительно файла TOML. Поэтому перед копированием конфигурации при включённых письмах используйте путь из примера `~/.local/state/vacancy-bot/profile`, а не `.local/profile` из исходного шаблона.

`daemon-reload` перечитывает unit-файлы; `enable --now` включает автозапуск и запускает службу сейчас. `enable-linger` позволяет пользовательскому менеджеру работать без активного SSH-входа и подниматься при загрузке машины. Это команда администратора для **вашего** пользователя; для настройки автозапуска нужны соответствующие права. Не запускайте её от имени другого аккаунта случайно. [Документация loginctl](https://www.freedesktop.org/software/systemd/man/latest/loginctl.html).

После этого можно закрыть SSH. Для чтения каналов нужен интернет; служба при аварийном завершении повторяет запуск через 30 секунд. Это не отменяет остановку доставки при её неопределённом результате: см. эксплуатацию.

```bash
journalctl --user -u vacancy-bot.service -n 50 --no-pager
systemctl --user restart vacancy-bot.service
systemctl --user stop vacancy-bot.service
```

Первая команда показывает последние 50 записей журнала, вторая перезапускает службу после изменений, третья останавливает до следующего запуска. Чтобы отменить автозапуск: `systemctl --user disable --now vacancy-bot.service`.

## Данные, дубли и сбои

- SQLite содержит исходные посты, правки, связи ссылок, очереди модели/писем и состояние отправки. Сохранённые письма и факты — личные данные владельца установки.
- Одинаковая каноническая ссылка конкретной вакансии помогает объединять репосты. Разные ссылки или переписанный текст могут остаться разными вакансиями; абсолютная дедупликация не обещается.
- Правка ещё не отправленной публикации обновляет или отменяет подготовку. После уже отправленной карточки её исходное содержимое и соответствующий файл сохраняются согласованными.
- Перед сетевой отправкой запись становится `inflight`. При подтверждении карточки сохраняется её ID, затем отдельно отправляется TXT через [Telegram sendDocument](https://core.telegram.org/bots/api#senddocument). Файл приходит без второго звукового уведомления.
- При 429 сохраняется задержка для всей очереди. При таймауте/неопределённости запись становится `uncertain`, и доставка приостанавливается. Нельзя безопасно гарантировать ровно одну отправку при потере сетевого ответа.
- Не удаляйте рабочую БД ради «починки»: это уничтожит историю и защиту от повторов. Перед обновлением делайте согласованную резервную копию SQLite; не копируйте только `.sqlite` из работающего WAL-набора обычным `cp`.

Read-only сводка без токена, текста писем и идентификатора получателя:

```bash
python3 -m jobbot.status --database "$HOME/.local/state/vacancy-bot/live.sqlite"
```

Устранение остановки доставки, резервное копирование и обновление: [docs/OPERATIONS.md](docs/OPERATIONS.md).

## Ограничения и статус универсальной версии

Публичный веб-просмотр Telegram показывает только последнюю страницу: во время длительного простоя старые публикации могут выйти за её пределы. Закрытые каналы, OCR картинок, вложения, массовый обход истории, подтверждение актуальности вакансии и автоматические отклики не реализованы. Изменение HTML Telegram может потребовать обновить парсер.

Это однопользовательская установка, не многопользовательский SaaS. Для другого человека — свой бот, конфигурация, профиль и база. Иное имя профессии в тесте или демо не подставляется в рабочую конфигурацию автоматически.

Версия экспортирована из работающего персонального бота и обобщена. Наследованы механизмы очереди, исходного снимка, защиты от повторов, карточек и TXT. Универсальные фильтры и нейтральные профили проверяются тестами; это не обещание качества на всех профессиях и не свидетельство новой реальной доставки в чужой чат. После своей привязки выполните явную проверку связи и оцените первые реальные карточки.

Не публикуйте `.local/`, `credentials.json`, `profile.json`, рабочие TOML, базы, CV, журналы и готовые письма. Они исключены через `.gitignore`, но уже отслеживаемый Git файл эта настройка не скрывает. Перед публикацией проверяйте `git diff --cached` и список подготовленных файлов.
